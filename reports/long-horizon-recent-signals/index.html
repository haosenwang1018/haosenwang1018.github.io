Long Horizon 近期工作地图

2026-06-29 · draft for report discussion · noindex

这页用工作图组织近期材料。它把 RL、机器人 world model、robot policy、coding agent、research agent 和 AI for Science 放进同一个问题里：一个系统要连续行动很久，怎样保存状态、预测未来、检查结果、修正计划，并让下一轮行动更可靠。

读这张图时，先问某篇论文改的是长期执行循环里的哪个接口：它是在减少预测漂移，保存任务状态，验证事件结果，缩短有效时域，还是让评估信号更可靠？

这张图想说明什么

不同领域使用 Long Horizon 时，benchmark 和研究对象经常不同。它更像一种系统压力：任务一变长，模型必须连续调用自己的状态、记忆、预测、验证和反馈。任何一个接口不可靠，错误都会进入后续循环。

在 model-based RL 里，问题最容易被写成 rollout drift：模型预测几步还可以，自己滚几十步以后状态开始偏。在机器人里，问题会变得更具体：杯子是否真的被放进柜子、抽屉是否真的被打开、接触是否进入了另一个动力学 regime。在 coding agent 里，问题变成了 spec、repo state、测试和工具执行记录能否跨长任务保存。AI for Science 更像一个上层类比：系统要在假设、实验、数据和证据之间循环很久，评估器一旦不可靠，后面的研究行动也会被带偏。

按接口看近期工作

接口 系统在问什么 近期工作怎么改 代表信号
Predict 模型想象未来时，误差从第几步开始影响决策？ 把像素预测换成 latent、3D point flow、task-oriented dynamics，或者让模型在自己的 rollout 上训练。 TD-MPC、PRISM-WM、PointWorld、Persistent Robot World Models。
Trust 系统怎样知道这次预测还能信多远？ 把 horizon 当成显式变量，或者根据 state/action 不确定性截断 rollout。 NEUBAY、Universal Horizon Models、Variable-Length Latent World Models、HWM。
Verify 未来画面看起来合理，任务事件是否真的成立？ 加入 predicate、event state、逆向验证、progress checker，让规划不只追逐视觉相似度。 EV-WM、H-WM、World Action Verifier、RoboReward、CoVer。
Plan planner 会不会专门利用 learned model 的盲区？ 把训练分布改到 planner 会访问的状态，或者把 future、action 和 value 放进同一个生成模型。 GRASP、Closing the Train-Test Gap、Cosmos Policy、DreamZero。
Act 长任务是否需要更粗的动作单位？ 用 action chunk、hierarchical control、high-level waypoint、human demo retargeting 缩短有效时域。 Puppeteer、Psi-Zero、A2A、VIRAL、EgoHumanoid。
Memory 系统如何保存物体、遮挡、子任务进度和历史失败？ 从短期视觉记忆、长期语言记忆、keyframe memory、object-centric state 到 persistent world/ego factorization。 MEM、Keyframe-Chaining VLA、World-Ego Modeling、Slot-MPC、Qwen-AgentWorld 的 agent-world state 类比。
Measure 一个 world model 好不好，究竟看视频质量还是看行动后果？ 把评价从 reconstruction/FVD 推向 policy ranking、closed-loop score、success rate、real-robot outcome。 World Models Survey、World Model for Robot Learning Survey、WorldArena、WorldEval。

按领域看同一个问题

领域 长期状态是什么 最常见的失败 最近的做法
Model-based RL latent state、reward、value、transition function。 rollout 变长后模型误差进入 value 和 action selection；planner 会放大模型盲区。 短 horizon MPC + terminal value；不确定性和可变 horizon；为 planner-induced states 做训练。
Robot world models 物体位置、接触状态、遮挡、任务事件、机器人姿态。 预测画面合理，但事件不成立；接触模式被平均；对象身份和任务进度丢失。 event verification、object/state persistence、3D dynamics、hierarchical task-motion world model。
Robot policy / VLA 语言目标、视觉上下文、action chunk、身体状态和 progress。 长任务被拆成太多底层控制步；动作延迟、自然度、恢复能力和跨本体迁移共同限制上线。 action chunking、hierarchical control、human video pretraining、retargeting、sim-to-real、flow policy。
LLM / coding agents repo state、spec、tests、工具结果、handoff notes、记忆。 长时间工作后忘掉原始目标，依赖可见测试，或者在上下文压缩后丢关键约束。 external memory、progress files、harness、tests/verifier、multi-session continuation、long-horizon coding benchmark。
AI for Science 假设、实验计划、数据、模拟器、分析脚本和证据链。 实验循环长，错误 evaluator、脏数据或错误日志会污染后续结论；agent 可能完成了流程但没有产生可信知识。 workflow logging、agent teams、simulation/checker、实验复现记录、human review。这个方向我还没有深读，只先放成类比坐标。
RSI 系统自己的能力模型、任务记录、评估器、改进策略和回归测试。 如果长链条里的反馈不可信，系统会把错误当成进步，持续自我强化。 更可靠的 verifier、regression suite、stateful memory、可审计改进记录。这里是上层目标，我还没有把它证明成一个具体选题。

对选题有用的五个观察

  • 1. Long Horizon 的核心在于让循环里的状态、预测和反馈在多次调用后仍然可信。 所以最值得追的问题通常是：哪个接口在长任务里最先失效。
  • 2. World model 方向里，最清楚的实验对象仍然是 rollout、planner 和 value。 TD-MPC、PRISM-WM、GRASP、NEUBAY 这类工作之所以适合学习，是因为它们能把“预测失败”落到任务回报、规划轨迹、horizon、ablation 上。
  • 3. 机器人方向把 long horizon 变成了更真实的状态问题。 对象是否还在、抽屉是否开过、接触是否换了模式、子任务是否完成，这些比“视频看起来像不像”更接近 long-horizon reliability。
  • 4. Coding agent 和 AI for Science 提供的是类比，不应该直接替代机器人问题。 它们提醒我：长期系统都需要外部状态、verifier、日志和回归测试。但机器人还额外受物理、接触、延迟和真实执行限制。
  • 5. 如果最终目标是 RSI，long horizon 就变成了可信自我改进的前置问题。 系统要反复行动、测量、更新自己；只要反馈链条不可靠，自我改进就可能变成错误累积。

后续读论文时的问法

下一步读每篇论文，可以固定问六个问题：它要证明什么？它认为旧系统在哪个接口失败？它改了 state、memory、predict、verify、plan、act、measure 中的哪一个？它在哪个平台暴露失败？它和谁比较？它用什么指标证明自己的主张？

这样读的好处是，论文不会散成名词列表。每篇工作都要回到同一条长期执行循环里，看它到底改了哪个零件，以及这个改动是否真的让长任务更可靠。
