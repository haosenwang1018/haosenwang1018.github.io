跨平台轨迹与评测接口

HumanoidArena 与 SIMPLE 的四条真实逐控制步轨迹已经进入同一套记录、验证和分析接口。

完成了什么

接口保留 observation、Policy request 与 action、Controller 输入输出、robot state、root 与 foot pose、contact / force、reward、success、termination、seed、版本和来源身份。

原始逐控制步轨迹 → 平台 adapter → 统一记录 → 公共 validator 与 analyzer

  • HumanoidArena success：537 个 transition，终止原因为 success。
  • HumanoidArena timeout：10 个 transition，终止原因为 timeout。
  • SIMPLE success：214 个 transition，终止原因为 task success。
  • SIMPLE 主动停止：120 个 transition，保留 censored 状态和停止原因。

验收结果

  • 37/37 项单元与对抗测试通过。
  • 16/16 类语义篡改按指定原因被拒绝。
  • 2/2 类源文件篡改被拒绝。
  • 17/17 个交付文件哈希核验通过。
  • Python 3.9、3.12 和 3.14 生成的验收结果与四份分析结果逐字节一致。
  • 独立质检重新运行完整门禁，结论为 PASS。

Force 的比较边界

同一平台内，measurement identity、单位、坐标系和来源一致时允许比较。HumanoidArena 与 SIMPLE 的 force 定义不同，跨平台结果明确返回 not_comparable，没有通过补零或归一化制造共同指标。

可检查证据

机器验收结果 · 独立质检

这项交付证明跨平台记录与评测基础设施可用。它没有选定最终 benchmark，也没有证明 Controller 效果或完成 Policy 训练。
