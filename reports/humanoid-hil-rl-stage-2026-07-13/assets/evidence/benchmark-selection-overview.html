Benchmark 选型进展

最终 benchmark 尚未确定。目前保留 BendPick、stationary OpenFaucet 和 G1 Powerlift，P&PBox 已退出默认方案。

要验证的科研问题

在上肢主导、stationary、接触丰富且下肢参与姿态或平衡的 humanoid 任务中，验证局部人工纠正数据能否在固定 Controller、无持续人工辅助的评估条件下提升 held-out 任务表现，同时避免接触安全与全身稳定性出现不可接受的退化。

这句话冻结了 benchmark 必须支持的研究结论；具体平台、任务、Policy 和 Controller 仍由证据决定。

本轮形成的产出

  1. 任务选择标准：把上肢主导、下肢贡献、stationary、force / compliance 价值、纠正窗口、实验闭环和 Controller 兼容性写成可检查条件。
  2. 三个候选的证据卡：分别记录保留理由、当前证据、最强反证和下一步验证。
  3. 候选定型与实测反证：补充 BendPick 的完整移动测量，以及 OpenFaucet 固定版本的动作与评测对象检查。
  4. Evaluator 对抗测试：定义任务完成、接触安全、stationary / 稳定性和终止原因，并用 16 个合成案例检查假成功。

对抗审查修正了什么

  • 代码中缺少 WalkSpec 只能说明未显式调用该模块，无法单独证明完整动作满足 stationary。
  • 官方数据和 checkpoint 只能证明平台具备基础资产，无法单独证明当前具体任务已经形成数据、Policy 与 evaluator 闭环。
  • 官方 expert action 主要作用于上肢，仍不足以证明上肢动作决定任务成败。
  • 关节角或物体高度可以描述任务进度，仍需接触、稳定保持和身体碰撞条件来排除假成功。

当前结论

三个候选都还没有同时冻结具体任务、数据与 Policy、Controller 插入位置和评测协议，因此尚未进入正式动态对照。当前保留顺序表示关闭关键未知项的成本，不表示永久科学排名。

  • BendPick：已有真实运行和上肢纠正证据；需要先完成 stationary 版本与稳定举升 evaluator。
  • stationary OpenFaucet：接触与顺应价值清楚；需要实现正确 handle 动作链和近身 stationary 配置。
  • G1 Powerlift：可形成独立平台路径；需要补齐 contact-aware evaluator、数据闭环和 Controller 接口。

本轮产出缩小了搜索空间，也明确了每个候选目前缺少的证据。它们尚未证明任何候选已经成为最终 benchmark。
